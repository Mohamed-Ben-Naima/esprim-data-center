1The lab in one page

What it is

The design study defined a production data center in Casablanca: 96 racks in two halls, about 1 MW of IT load, with a Rated-3 resilience target (any critical component can be maintained or can fail without stopping the service). This lab reproduces the network of that data center inside GNS3, on a personal PC, to prove the design works and to measure how fast it recovers from failures.

The design idea: everything exists twice

  • Two Internet providers (ISP-A primary, ISP-B backup).
  • Two edge routers speaking BGP to both providers.
  • Two firewalls in an active/passive cluster.
  • Two core switches sharing the gateway role per VLAN.
  • Leaf switches in pairs, one pair per hall.
  • Servers with two network cards, one to each leaf of the pair.

Traffic normally uses the "A" side. If any A device stops, its B twin takes over automatically in a few seconds or less. A virtual IP address (HSRP on Cisco, CARP on pfSense, keepalived on servers) moves from the failed device to its twin, so neighbours never need to be reconfigured.

Security is deny by default: only the flows listed in the policy are allowed, everything else is blocked and logged.

How it is built: one source of truth

Nothing is typed by hand on the devices. One file, inventory/dc_casa.yaml, describes the whole network (VLANs, addresses, ports, rules, tests). Scripts read it, generate every configuration, push them to the device consoles through the GNS3 API, collect proof and fill the report tables. To change the network you change the inventory and re-run the generators.

Traffic between internal VLANs (for example an app server mounting NFS on the storage server)

VLAN 20 to VLAN 30 is routed directly by the core switch and never crosses the firewall. The core applies an inbound access list on each VLAN interface: only the declared flows pass (here TCP/UDP 2049, 111 and TCP 3260), the rest is dropped and logged.

Administration

Device management ports live in VLAN 10 (out of band). The cores and edges put that port in a separate routing table (VRF MGMT), so user traffic can never reach it. The only way in is from the admin zone (VLAN 90: bastion and admin workstation) through the firewall, with SSH or HTTPS.

5Device by device

For each family: its role, what it does, and the configuration that makes it do so. The full files are in configs/. The B device is always the same as A except for addresses and priorities.

5.1 ISP-A and ISP-B - the simulated Internet providers

Role. Play the two operators the data center buys Internet from. They are FRR routers in containers; their third interface goes to a GNS3 NAT cloud, so traffic really reaches the Internet.

  • eBGP session to both edge routers (4 sessions in total across the two ISPs), protected by an MD5 password, timers 3 s / 9 s.
  • Sends only a default route to the customer (default-originate, everything else denied outbound).
  • Accepts only 192.0.2.0/24 from the customer, maximum 10 prefixes.
  • IP forwarding + masquerade on eth2 towards the real Internet.
! configs/ISP-A/frr.conf (extract)
router bgp 64500
 neighbor 198.51.100.2 remote-as 65100
 neighbor 198.51.100.2 password Bgp-DC-2026
 neighbor 198.51.100.2 timers 3 9

  neighbor 198.51.100.2 default-originate
  neighbor 198.51.100.2 prefix-list PL-FROM-DC in
  neighbor 198.51.100.2 route-map RM-DENY-ALL out
  neighbor 198.51.100.2 maximum-prefix 10

5.5 LEAF-A1, A2, B1, B2 - access switches (Cisco IOSvL2)

Role. Connect the servers. Pure layer 2 (no ip routing): they carry VLANs up to the cores and do not route.

  • Two uplinks, Gi0/0 to CORE-A and Gi0/1 to CORE-B, both trunks for VLAN 20, 30, 40, 60, 70, 80, 100. Spanning tree forwards each VLAN on the uplink towards "its" core and keeps the other as standby.
  • Server ports: access mode, portfast + bpduguard (a switch plugged by mistake disables the port; automatic recovery after 300 s).
  • Unused ports: access VLAN 999 and shut down.
  • Management: VLAN 10 interface (10.10.0.31 to .34) on a dedicated port to SW-MGMT; VLAN 10 is never carried on the uplinks.

5.9 Hardening common to all Cisco devices

  • SSH version 2 only, no telnet, no HTTP server.
  • Local accounts with AAA; 5 failed logins in 60 s block logins for 120 s; successes and failures logged.
  • Remote access (VTY) only from VLAN 90 (admin) and VLAN 60 (monitoring): ACL-MGMT-ACCESS.
  • Session timeout 10 minutes, legal banner.
  • SNMP version 3 with authentication (SHA) and encryption (AES-128), user zbxmon; traps to 10.60.0.11.
  • Logs with millisecond timestamps to 10.60.0.12; clock from 10.100.0.11.
  • Passwords stored encrypted; no source routing, no proxy ARP, no redirects.
  • Interface descriptions follow the TIA-606 labelling: MDA-CORE-A:Gi1/0 -> HDA-A-LEAF-A1:Gi0/0.

Each internal VLAN interface on the cores has an inbound list built in the same order:

  1. Replies of already-open TCP sessions, and HSRP / VRRP hellos.

  6. Allow the rest (Internet): it goes to the firewall, which filters it again.
